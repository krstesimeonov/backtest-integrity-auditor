an optional Streamlit presentation layer over those same services. V1.2 adds

exact vectorbt `1.1.0`, bt `1.2.0`, and Backtrader `1.9.78.123` results.
V1.5D3 completes the roadmap with exact QuantConnect LEAN `2.5.17999` and
NautilusTrader `1.231.0` adapters plus complete-registry conformance. V1.5E
adds explicit, fail-closed strategy, instrument/symbol, currency, timestamp,

adds deterministic alignment and exact field comparison. V1.5G measures
transaction-cost, sizing, accounting, and return divergence without scoring or

independent golden/reference cases, generated invariants, performance budgets,
installed-wheel checks, bounded file boundaries, atomic report output, and

report schema `2.5`, V1 audit-run-manifest schema `1.1`, and database schema `1`

The Single-Run and Experiment-Family public contracts are complete for V1.

## Accepted V1 completion state

The technical V1 release scope is complete:

- Machine-readable report, profile, and manifest contracts are packaged and
  documented with stable IDs.
- CI verifies supported Python versions, deterministic generated contracts,
  formatting, lint, focused static typing, coverage, build metadata, clean
  installation, installed resources, and byte-for-byte CLI output.
- Complete golden reports, independent numerical reference data, and a
  deterministic scalability harness are part of the source release.

Public distribution still requires owner-controlled choices such as the
software license, repository URL, release tag, and publication destination.
Those choices are operational/legal release decisions, not missing V1 audit
functionality.

## Interpretation boundaries frozen at V1

- PBO asks how often an IS winner ranks at or below the OOS median across CSCV
  splits. PSR and DSR answer different questions.
- CSCV uses selection-eligible completed trials. Failed attempts retain search
  provenance but never receive fabricated performance curves.
- External split metadata is separate research-design evidence; it is not
  silently substituted for symmetric CSCV partitions.
- Equal partitions are required. Remainders and undefined split metrics cause a
  typed unavailable result rather than deletion.
- PBO is an audit diagnostic, not an objective for choosing parameters.
- Parameter neighborhoods use only tested selection-eligible trials. Unscaled
  parameters remain exactly fixed, and zero-distance duplicates are listed but
  never counted as independent neighbors.
- The local geometry is conditional on explicit scales and radius. The auditor
  does not expand a sparse neighborhood or drop an undefined neighbor.
- Equal temporal windows require exact divisibility and at least two
  observations per window; no remainder or undefined trial score is removed.
- Declared folds replay their own IS winner into OOS and remain separate from
  equal-window summaries and CSCV partitions.
- Equal windows provide a limited descriptive stability view, not a formal
  structural-break test, and their Sharpe values are not HAC-adjusted.
- Evidence dimensions are independent. There is no total score, global pass,
  or rule that lets one supported dimension offset another fragile, ineligible,
  or insufficient dimension.
- `supported_under_stated_assumptions` never certifies skill, profit, or future
  performance.
- Time-varying risk-free returns are additive evidence and never silently
  replace scalar risk-free assumptions in earlier Sharpe/PSR/HAC/family methods.
- Declared regimes are external labels, not inferred states or structural-break
  tests.
- White Reality Check and SPA require the complete selection-eligible family
  and a shared aligned benchmark; winner-only evidence remains ineligible.
- ACF, PACF, runs, Ljung–Box, effective observations, and variance ratios test
  different dependence features. Non-rejection does not establish IID returns.
- Audit time and Git identity are explicit producer declarations; neither is
  inferred, and the Git identity is not independently verified.
- Raw-file hashes identify bytes. The normalized-data hash identifies canonical
  semantic input after validated ordering. The configuration hash identifies
  declarations and audit choices. These identities must not be conflated.
- The final manifest hash intentionally includes method, dependency, and
  environment versions, so a different environment produces a different run
  identity even when data and configuration hashes match.

## Explicitly outside V1

- Broker connectivity other than the explicit read-only IBKR Flex V1.3 adapter;
  all order execution, custody, money movement, and live trading.
- Cross-engine trade/fill/position reconciliation; that is V1.5.
- Options-chain simulation, fills, assignment, and expiration; that is V2.
- Portfolio Greeks, stress testing, margin, and tail aggregation; that is V3.
- Broker-trade reconstruction and realized edge attribution; that is V4.
- Live edge-decay monitoring and alerts; that is V5.
- Microservices, a database-first rewrite, or a public multi-user web service.
  The local Streamlit adapter remains file-first and has no authentication;
  V1.2 persistence is an optional single-application audit-history adapter and
  V1.3 API import is an explicit read-only action.

## Recommended next development increments

Treat V1.4 as the completed advanced-statistics increment and V1.5A–J as the
completed implementation-risk path. The next planned product increment is V2,
the Honest Options Backtester. Before starting V2, owner-controlled publication
choices for V1.5 may be completed independently if public distribution is
desired.

Concrete engine exports must still map through the V1.5C port into the
unchanged V1.5B domain; engine-specific terminology must not enter comparison
services. Cross-engine reconciliation remains file-first and includes no order
execution.

Do not add V1.5 fields informally to report schema `2.5`; make an explicit
schema-version decision before changing any frozen public object.
